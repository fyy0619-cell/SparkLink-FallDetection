# 银尔达 DTU 配置平台操作指南（注册 → 添加设备 → 分组 → 任务 → 更新）

本文记录把 **V100C / Air780EHV 4G DTU** 接入银尔达 web 配置平台、并把跌倒报警「任务」脚本
下发到设备运行的**完整操作流程**。配套的链路实现与调试复盘见同目录
[`4G_DTU_call_sms_guide.md`](./4G_DTU_call_sms_guide.md)。

> 平台界面会随版本变化，下文按钮/页签名称以你登录后的**实际界面为准**；本文重点是**流程顺序**和
> **本项目用到的具体参数**。

---

## 1. 整体流程总览

```text
注册账号
    │
    ▼
添加设备（输入并验证 IMEI）
    │
    ▼
创建分组（分组型号必须与设备型号一致）
    │
    ▼
把设备分配到分组
    │
    ▼
配置参数：串口参数 + 基本参数 + 上传「任务」Lua 脚本
    │
    ▼
确认「自动更新参数」为开 → 保存
    │
    ▼
重启 DTU（断电重启 / 自动重启）→ 设备上电拉取最新参数
    │
    ▼
校验：设备列表「分组参数版本」== 「设备参数版本」→ 更新成功
```

**核心概念**：银尔达平台里，参数和任务都是**按「分组」下发**的，单台设备只是被分配进某个分组；
设备**重启时**才会去服务器拉取分组的最新参数/任务，靠「参数版本号」判断是否拉到。

## 2. 平台与文档入口

- 官方教程库（语雀）：`yinerda.yuque.com`（4G DTU 教程），首次使用务必先看其中的
  **《WEB 配置入门教程》**（涵盖添加设备、创建分组、分配设备）。
- web 配置平台：用注册的账号登录后操作。
- 注：语雀文档可能被网络策略拦截，打不开时可换网络或让对方截图（见 call_sms_guide 复盘 #1）。

---

## 3. 注册账号

1. 打开银尔达 web 配置平台，注册并登录。
2. 新账号下**没有任何设备**，需要自己在设备列表里逐台添加（见第 4 节）。

---

## 4. 添加设备

1. 进入「设备列表」→「添加设备」。
2. 填入设备 **IMEI**（在 DTU 机身标签 / 包装盒上），平台会校验。
3. **SN 不需要、也不能填**，只认 IMEI。
4. 若 IMEI 填对了仍提示「设备不存在」→ 说明该设备**未授权**，需联系销售生产授权后才能添加。

---

## 5. 创建并分配分组

分组是**参数 / 任务下发的核心单元**，必须先有分组才能下发配置。

1. 创建分组时要选「设备型号」，该型号**必须和你设备的实际型号一致**，否则后面无法把设备分配进来。
   - 型号对不上 → 联系销售核实 / 处理。
2. 把设备分配到分组：
   - 选择第 4 节添加好的设备；**已经分配过分组的设备不会出现在可选列表里**。
   - 列表为空时，先回去确认设备是否已添加。
   - 分配成功后分组里会显示该设备。
3. **变更分组**的规则：
   - 设备与目标分组的型号必须一致；
   - 换分组前要**先把设备从原分组移除**；
   - 改完参数要**保存并重启设备**才生效。

---

## 6. 配置串口与基本参数

在分组的参数配置里设置（本项目用到的关键值）：

| 配置项 | 本项目取值 | 说明 |
|---|---|---|
| 串口波特率 / 数据位 / 校验 / 停止位 | **115200 / 8 / 无 / 1** | 与 WS63 侧 `UART_BUS_1` 一致 |
| 打包超时 | **80 ms** | 串口分包/粘包打包间隔 |
| 自动更新参数 | **开**（默认开） | **关了设备就永远不会更新**，除非本地恢复出厂 |
| DTU 日志输出（基本参数页） | 调试时**开** | 看日志需 USB 线接 DTU + Luatools |

> 重要：WS63 实测接在 DTU 的**串口 id = 2**（不是 id 1）。任务脚本里 `UartGetRecChAndDel()`
> 必须用 `2`。详见 `4G_DTU_call_sms_guide.md` 第 7 节复盘 #9。

## 7. 添加 / 编写「任务」（Lua 脚本）

银尔达 DTU 的高级数据处理通过**「任务」或「数据模板」**（Lua 二次开发）实现，可做协议转换、
数据解析、自定义打包/上报等。本项目用「任务」来收 WS63 串口数据并拨号 / 发短信。

1. 进入分组参数里的「任务」，把项目脚本**整段粘贴**进去，保存。
2. **脚本格式约定**（不遵守会上传报错，详见 call_sms_guide §6）：
   - 必须以**裸 `function` 开头、`end` 结尾**（不带函数名、不带 `()`，平台自己包装）；
   - **第一行必须就是 `function`**，前面不能有空格、空行或 `--[[ ]]` 块注释；
   - 函数体内只能用 `--` 单行注释；整个配置上限约 50K。
3. 本项目对应脚本（WS63 工程 `application/samples/my_demo/fall_detect/` 下）：

| 脚本 | 用途 |
|---|---|
| `dtu_task_fall_alert.lua` | **正式任务**：收 WS63 JSON → `cc.dial` 拨号 + `SmsSend` 发短信（`uid=2`） |
| `dtu_task_selftest.lua` | 自测：DTU 上电自己拨号+发短信，验证 DTU 自身能力 |
| `dtu_task_uarttest.lua` | 串口诊断：同时监听串口 1/2/3，定位 WS63 接的是哪个 id |

## 8. 参数 / 任务更新机制（远程 OTA）

改完串口参数或任务脚本后，**不会立刻生效**，要走一遍更新流程：

1. 在平台**保存**分组参数（此时分组「参数版本」会 +1）。
2. **重启 DTU**：断电重启或等其自动重启。
3. 设备上电后会访问 web 平台拉取最新参数；**连续请求 5 次**，若都失败则继续按旧参数运行。
4. 必须保证「自动更新参数」是**开**的，否则设备永远不会去拉新参数。
5. **校验是否更新成功**：在设备列表查看，当某台设备的
   **「设备参数版本」追上「分组参数版本」**，即代表它已拉到最新参数/任务。

## 9. 调试与验证

- **平台模拟器**：设备详情 →「设备调试」→ 引用模拟器，可向设备下发数据测试任务是否正确应答。
- **本项目可观测信号**（手头没有 USB 调试线时）：直接看**目标手机是否响铃 / 收到短信**，
  配合 `selftest` / `uarttest` 两个最小脚本逐环隔离定位。
- **看 DTU 日志**：需 USB 线接 DTU + Luatools，并在平台「基本参数」页把「DTU日志输出」打开。

完整验收步骤（DTU 侧 + WS63 侧）见 `4G_DTU_call_sms_guide.md` 第 9 节。

## 11. 常见坑（FAQ）

| 现象 | 原因 / 处理 |
|---|---|
| 添加设备提示「IMEI 不存在」 | 设备未授权 → 联系销售生产授权 |
| 设备无法分配进分组 | 分组型号与设备型号不一致 → 重建对的型号分组 / 联系销售 |
| 改了参数设备一直不更新 | 「自动更新参数」被关 → 打开；或没重启设备 |
| 任务上传报 `function arguments expected near '...'` | 脚本第一行不是裸 `function`（被空行/块注释顶下去了） |
| 改完任务不生效 | 没保存 / 没重启 / 参数版本没追上，按第 8 节重走 |
| 电话打不出 | SIM 非移动联通普通卡、没开 VoLTE、或固件 < V1.1.13（见 call_sms_guide §4） |
