# WS63 开发板上手指南

从「拿到开发板」到「代码在板子上跑起来、能测试」的完整流程。面向第一次拿到 WS63 开发板、没用过 HiSpark Studio 的同学，每一步都讲清楚。

整个流程一张图：

```text
拿到开发板 → 装 HiSpark Studio → 打开工程 → menuconfig 配置
   → 编译 → 烧录 → 串口看日志测试 → (可选) 在线调试
```

---

## 1. 第一步：认识 WS63 开发板

WS63 是海思的一颗 Wi-Fi 6 + 蓝牙 + 星闪(SLE)SoC，**RISC-V 架构**。开发板把这颗芯片连同供电、USB、按键、排针都引出来，方便开发。

拿到板子先认几个关键部件：

| 部件 | 作用 |
| --- | --- |
| **USB 口(Type-C)** | 接电脑。一根线同时负责供电 + 串口通信，烧录和看日志都靠它 |
| **RESET / 复位键** | 按一下重启程序，烧录和测试时都会用到 |
| **排针 / GPIO** | 接外设。本项目 MPU6050 接在 GPIO15(SDA)、GPIO16(SCL) |
| **板载 LED** | 程序跑起来一般会有灯闪，可作为「活着」的最直观信号 |

> 小白提示：WS63 是 **RISC-V**，不是 ARM，也不是 STM32。所以工具链、调试器那一套和 STM32/Keil 完全不同 —— 别去找 `arm-none-eabi-gcc`。

用 USB 线把开发板插到电脑。第一次插上，Windows 会自动安装串口驱动。

---

## 2. 第二步：确认串口(COM 口)

烧录和看日志都靠串口，先确认电脑认到了板子：

1. 右键「此电脑」→ 管理 → 设备管理器
2. 展开「端口(COM 和 LPT)」
3. 看到类似 `USB-SERIAL CH340 (COM8)` 或 `USB Serial Port (COMx)` —— 记下这个 **COM 号**

> 如果没有这一项，说明 USB 转串口驱动没装好。常见的转串口芯片是 CH340 / CP2102，去对应官网下驱动装上再插一次。
>
> 本工程 `demo.hiproj` 里记录的烧录串口是 `COM8`，你的电脑不一定是 8，以设备管理器实际看到的为准。

---

## 3. 第三步：下载并安装 HiSpark Studio

**HiSpark Studio 是什么**：海思官方的开发 IDE，基于 VSCode 定制而成。它把「编辑代码 + 配置(menuconfig)+ 编译 + 烧录 + 调试」整合在一个界面里，并且**自带 RISC-V 工具链**，你不用单独装编译器。

安装步骤：

1. 到海思官方开发者渠道(如 HiSpark 社区)下载 HiSpark Studio 安装包。本工程使用的版本是 **26.2.1**。
2. 运行安装包，按默认选项装好。
3. 启动 HiSpark Studio，界面和 VSCode 几乎一样，左侧多了海思的工程 / 编译 / 烧录面板。

> HiSpark Studio 本质是一个 VSCode 扩展(`hispark.hisparkstudio`)+ 一套定制环境。装好后工具链(`cc_riscv32_musl_fp_win`)就在它的安装目录里，编译时自动调用，无需你配 PATH。

---

## 4. 第四步：用 HiSpark Studio 打开本工程

本工程根目录有个 `demo.hiproj` 文件 —— 这就是 HiSpark Studio 的工程描述文件。

1. HiSpark Studio → 打开工程 / Open Project
2. 选中工程根目录（含 `demo.hiproj`、`build.py`、`application/` 的那一层）
3. 打开后，HiSpark Studio 会识别出这是一个 WS63 LiteOS 工程，编译目标是 `WS63-LITEOS-APP`

`demo.hiproj` 里已经配好的关键信息（一般不用改）：

| 项 | 值 | 含义 |
| --- | --- | --- |
| board | ws63 | 目标开发板 |
| target | WS63-LITEOS-APP | 编译目标 |
| tool_chain | cc_riscv32_musl_fp_win | RISC-V 工具链（自带） |
| 烧录协议 | serial | 走串口烧录 |
| 烧录波特率 | 921600 | 烧录速度 |

---

## 5. 第五步：配置功能(menuconfig)

WS63 SDK 用 **menuconfig** 图形菜单决定「这次编译哪些功能」。要让跌倒检测程序被编进固件，需要在菜单里把它打开。

1. 在 HiSpark Studio 里打开 menuconfig（SDK 配置 / Menuconfig 入口）。
2. 按下面这条「套娃」路径，逐层进入并打开：

```text
Enable Samples (SAMPLES_ENABLE)
  └─ Enable the Sample of MY_DEMO          (ENABLE_MY_DEMO_SAMPLE)
       └─ Support Fall Detect AI Sample    (SAMPLE_SUPPORT_FALL_DETECT)
            └─ Enable Fall Detection Application   (ENABLE_FALL_DETECT_APP)
                 ├─ Use SLE (NearLink) instead of BLE   ← 用星闪通信
                 └─ Device Role: Server / Client        ← 这块板子是采集+AI还是接收端
```

3. 保存退出。menuconfig 的结果会写进配置文件，下次编译生效。

> 本项目是双板方案：一块选 **Server**（接 MPU6050、跑 AI、发报警），另一块选 **Client**（收报警）。给传感器板烧录时选 Server。

---

## 6. 第六步：编译

点 HiSpark Studio 的**编译 / Build** 按钮。它底层会调用工程根目录的 `build.py`，用自带的 RISC-V 工具链把整个工程编译成固件。

- 第一次编译较慢（要编 LiteOS 内核、蓝牙/星闪协议栈、Edge Impulse SDK 等），耐心等几分钟。
- 编译信息打印在下方输出窗口，看到类似 `build success` 即成功。
- 产物固件：`output/ws63/fwpkg/ws63-liteos-app/ws63-liteos-app_all.fwpkg`
  - `.fwpkg` 是海思的固件打包格式，烧录烧的就是它。

> 命令行也能编：工程根目录执行 `python build.py ws63-liteos-app`，HiSpark Studio 的编译按钮做的就是这件事。
> 编译报错先看输出窗口里**第一条** error；C++ / Edge Impulse 相关的链接报错，见同目录《C++编译链移植到LiteOS》。

---

## 7. 第七步：烧录到开发板

「烧录 / 下载」就是把上一步的 `.fwpkg` 固件写进开发板的 Flash。

1. 确认开发板已用 USB 连到电脑。
2. 在 HiSpark Studio 里找到**烧录 / Burn / Download** 按钮。
3. 确认烧录串口选的是第 2 步记下的 COM 号，波特率 `921600`。
4. 点烧录。HiSpark Studio 会：
   - 复位开发板进入烧录模式（本工程 `reset=1`，一般自动复位；若卡住，手动按一下板上 RESET 键）
   - 把 `.fwpkg` 写进 Flash，显示进度条
5. 看到 `烧录成功 / success`，烧录完成。

> 烧录失败常见原因：
> - COM 口选错，或被别的程序（串口助手等）占用 → 关掉占用串口的软件再试
> - 没进入烧录模式 → 点烧录后立刻按一下 RESET
> - USB 线只能供电不能传数据 → 换一根质量好的数据线

---

## 8. 第八步：测试 —— 用串口看日志

烧录完，程序就开始在板子上跑了。怎么知道它跑得对不对？**看串口日志**。

1. 用串口工具连开发板：HiSpark Studio 自带串口终端，也可用 SecureCRT / 串口助手 / VSCode 串口插件。
2. 串口参数：**COM 号**（同上）、波特率 **115200**、数据位 8、无校验、停止位 1（即 `115200 8N1`）。
   - 注意：**烧录用 921600，看日志用 115200**，两个波特率不一样，别搞混。
3. 按一下开发板 RESET 键，让程序从头跑。

如果跌倒检测程序正常，串口会打印类似：

```text
[System] Fall Detect Task Registered to LiteOS!
[System] Running in SERVER mode (Board A).
[AI] model ready: 256 samples, 6 axes, 200 Hz, interval=5 ms
[MPU6050] Wakeup success
[MPU6050] cfg: accel=+/-4g gyro=+/-500dps dlpf=44Hz sample=200Hz ...
[AI] collecting window: 120/256 samples ...
[AI] status=normal ai_fall=2% normal=98% gate=NO confirm=0/2 ...
```

**测试判据**：

- 静止放着 → 一直 `status=normal`，不报警
- 模拟跌倒（快速翻转 / 摔到软垫上）→ 出现 `status=FALL_RISK`，灯带变红

看到这些，就说明从开发板到代码的整条链路全通了。

---

## 9. (可选)在线调试

如果要单步调试、看变量，需要 J-Link 调试器（SWD 接口）。`demo.hiproj` 里调试配置已是 `jlink + swd`。把 J-Link 接到板子的 SWD 排针，HiSpark Studio 里点「调试」即可进入断点调试。

日常开发用串口 `printf` 看日志通常就够了，不一定要 J-Link。

---

## 10. 常见坑速查

| 现象 | 原因 / 解决 |
| --- | --- |
| 设备管理器里没有 COM 口 | USB 转串口驱动(CH340/CP2102)没装 |
| 第一次编译特别慢 | 正常，要编内核+协议栈+AI SDK，等几分钟 |
| 烧录卡住不动 | 串口被占用 / 没进烧录模式，按 RESET |
| 串口日志是乱码 | 波特率不对，看日志要 `115200`（不是烧录的 921600） |
| 串口没有任何输出 | COM 选错 / 接线问题 / 固件没烧进去，按 RESET 再看 |
| menuconfig 里找不到跌倒检测 | 没逐层打开 SAMPLES → MY_DEMO → FALL_DETECT |
