# 任务 · 调度器 · 优先级 —— 何时该建任务、给什么优先级、写在哪才会跑

> 承接 [信号量与消息队列](信号量与消息队列-稳定采样流水线.md)。上一篇讲"任务之间怎么传节拍/数据"，本篇讲**任务本身**：怎么创建、单核怎么"同时"跑多个、何时该建任务、以及"写在哪才会真跑"。
> 对应源码：`main_task.c` 的 `osThreadNew(Sample_Task_Body, ...)`。

---

## 🔑 核心要点

> **① 任务 = 一段独立、能被 RTOS 调度的执行流。`while(1)` 这种"要一直跑的循环"不能直接调用，必须 `osThreadNew` 建成任务。**
> **② 单核只能跑一个，靠调度器按【优先级】飞快切换制造"同时"的错觉。高优先级任务一 Ready 就【抢占】。**
> **③ 任务函数写哪个 .c 都行，但"创建它的 `osThreadNew`"必须在【开机会被执行到的路径】上，才会真跑。**

---

## 一、创建任务在干嘛、为什么需要

```c
osThreadAttr_t attr = {0};
attr.name       = "ImuSampler";          // 任务名(调试时认它)
attr.stack_size = SAMPLE_TASK_STACK_SIZE;// 每个任务独立的栈(不够会栈溢出崩)
attr.priority   = osPriorityAboveNormal; // 优先级
if (osThreadNew((osThreadFunc_t)Sample_Task_Body, NULL, &attr) == NULL) { ...失败... }
//               要跑的函数            参数  属性
```

**为什么必须建任务、不能直接调？**
`Sample_Task_Body` 是 `while(1)` 死循环——你一调进去就**永远不返回**，后面全卡死。所以把它**交给 RTOS 当"任务"创建**，由调度器让它和别的任务（推理/SLE/监控）**并发轮流跑**。
> 就像"雇一个专职采样员独立上班"，而不是"你自己站那儿一直采、啥别的都干不了"。

**两个字段重点：**
- **`stack_size`**：每个任务有**自己独立的栈**（放局部变量、函数调用）。**必须给够**，太小会栈溢出崩溃。
- **`priority`**：见下一节。采样给 `AboveNormal`（高于普通），保证能及时响应 5ms 节拍。

## 二、单核怎么"同时"跑多任务：调度器 + 优先级

> **真相：WS63 应用核是单核，同一时刻只能跑一个任务。"同时"是调度器快速切换制造的错觉。**

### 任务的三种状态
| 状态 | 意思 |
|---|---|
| **Running** | 正占着 CPU 跑 |
| **Ready** | 想跑，排队等 CPU |
| **Blocked** | 在**等东西**（等信号量/队列/`osDelay`），**此时不抢 CPU** |

### 调度规则：谁 Ready 且优先级最高就跑谁；高优先级可【抢占】
低优先级任务正跑时，一个高优先级任务突然变 Ready（比如它等的信号量被 release），调度器**立刻打断低的、先跑高的**。

### 用采样 vs 推理走一遍
```
平时: 推理(低优先级)在跑; 采样阻塞在 acquire(不抢CPU)
5ms到 → 中断 release 信号量 → 采样变 Ready(高优先级)
     → 调度器【抢占】推理，马上跑采样
采样: 读IMU → 入队 → 回到 acquire → 【阻塞】(等下一拍)
     → 调度器恢复推理接着跑
```

> ⭐ **关键洞察：高优先级 ≠ 跑得多，而是"Ready 时优先跑"。**
> 采样优先级高，但**大部分时间阻塞在信号量上**（睡着），只每 5ms 醒一小下——占 CPU 很少却能瞬间响应，不会饿死推理。
> ⚠️ **反面**：高优先级任务若**从不阻塞**（死循环不睡），会**独占 CPU、饿死低优先级任务**。所以高优先级任务**必须经常阻塞**。

同优先级的多个任务，则**轮流切片（round-robin）**。

## 三、什么时候该建任务？（判断标准）

### ✅ 该建任务（满足任一条）
1. 有一段**要"一直运行"的循环**（`while(1)`）。
2. 要和别的逻辑**并发/独立**跑。
3. 需要**独立的节奏/优先级**（如采样高、推理低）。
4. 会**阻塞等待**（等信号量/队列/延时）。

### ❌ 不该建任务（用别的）
| 场景 | 用什么 | 例子 |
|---|---|---|
| **一次性初始化/配置**，做完就完 | **直接函数调用** | `sle_uuid_server_add()`、`ws2812b_init()` |
| **别人触发才跑一下** | **回调** | `sample_timer_cb`、`notification_cb` |
| **中断里的极短活** | **回调/ISR**（绝不建任务） | 定时器回调只 release 信号量 |

### 判断口诀
```
"要一直跑的并发循环、会阻塞等待"吗？ → 建任务
"做完就完的一次性动作"吗？          → 直接调函数
"别人触发才跑一下"吗？              → 回调
```

### 对照本项目
| 逻辑 | 任务? | 为什么 |
|---|---|---|
| `Sample_Task_Body` / `Fall_Detect_Task_Body` | ✅ | while(1)、并发、有优先级、会阻塞 |
| WS2812B 闪灯、告警守护 | ✅ | 要一直跑的循环 |
| `sample_timer_cb` / `notification_cb` | ❌ 回调 | 事件触发才跑一下 |
| `sle_server_task_init` / `sle_uuid_server_add` | ❌ 直接调 | 一次性，做完返回 |

## 四、任务"写在哪"才会跑？（高频困惑）

> ⭐ **任务函数（`Sample_Task_Body` 等）写在哪个 .c 都行；但"创建它"的 `osThreadNew` 必须在【开机会被执行到的路径】上，任务才会真跑。**

本项目的启动链：
```
main.c 的 app_main()
   → Fall_Detect_Entry()          (main.c 里【显式调用】)
      → sampling_pipeline_start()
         → osThreadNew(Sample_Task_Body)   ← 采样任务在这里才真正被创建
```

- **不是"写在主函数"**，而是**"创建它的那句要能被启动流程调到"**。
- **任务里还能再建别的任务**（嵌套），不必都堆在 main。

### ⚠️ 两个易混文件（本项目特有的坑）
| 文件 | 是什么 |
|---|---|
| **`main.c`**（`application/ws63/ws63_liteos_application/main.c`） | 系统**启动总入口**，`app_main` 在这里一句句显式调各个 `_Entry`。**要让新任务开机跑，就在这加一句调用。** |
| **`main_task.c`**（`.../my_demo/fall_detect/src/main_task.c`） | 只是 fall_detect 的**业务任务实现**，名字带 main 但**不是**启动入口。 |

> 本项目**不走 `app_run` 自动注册**，全靠 `main.c` 显式调用（源码注释：`// 显式调用，打破链接器死代码优化`）。所以新增一个开机任务，标准做法是：在 `main.c` 里 `extern` 声明入口 + 在 `app_main` 里调一次（`TimerHello_Entry()` 就是这么接进去的）。

## 五、练习：加一个"每 10 秒上报电量"（该用任务还是回调？给什么优先级？）

**决策**：要重复跑 + 会睡等 → **建任务**；不紧急不精确 → **低优先级 + `osDelay`**。

```c
static void Battery_Report_Task(void *arg)
{
    (void)arg;
    while (1) {
        uint32_t mv = read_battery_mv();               // 读电量(示意)
        osal_printk("[Battery] %u mV\r\n", mv);
        osal_msleep(10000);                            // 睡10秒(不精确也行)
    }
}

void Battery_Report_Entry(void)
{
    osThreadAttr_t attr = {0};
    attr.name       = "BatteryReport";
    attr.stack_size = 1024 * 2;                        // 活儿简单给小点
    attr.priority   = osPriorityBelowNormal;           // 低优先级,不跟采样抢
    if (osThreadNew((osThreadFunc_t)Battery_Report_Task, NULL, &attr) == NULL)
        osal_printk("[Battery] task create failed\r\n");
}
// 接入运行:在 main.c 的 app_main 里 extern + 调 Battery_Report_Entry();
```

**需求变了，答案就变：**
| 需求 | 该用 |
|---|---|
| 精确每 10.000 秒 | **硬件定时器**（要精度） |
| 电量低于 20% 才报 | **回调/事件**（事件触发，不是循环） |

---

## 六、一句话

> **建任务** = 把"要一直跑的并发循环"交给 RTOS 调度（`while(1)` 不能直接调）；
> **调度器**按**优先级**在单核上飞快切换制造"同时"，高优先级一 Ready 就抢占，但**必须常阻塞**才不饿死别人；
> **判断**：要重复跑/会阻塞→任务，一次性→直接调，事件触发→回调；
> **写哪才跑**：任务函数写哪都行，但**创建它的 `osThreadNew` 要能从开机入口（`main.c` 的 `app_main`）被调到**。
