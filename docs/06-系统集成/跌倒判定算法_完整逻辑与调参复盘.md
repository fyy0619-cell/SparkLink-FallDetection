# 跌倒判定算法 —— 完整逻辑与调参复盘

本文讲清楚「板 A 如何判断一次真实跌倒」的**完整逻辑**、**每种数据背后的物理意义**，
以及调参过程中遇到的全部问题与解决路径，方便复盘。代码在 WS63 工程
`application/samples/my_demo/fall_detect/`，核心文件 `src/fall_algo.c`、`src/main_task.c`。

## 1. 总体设计:B + NN 混合判定

```text
200Hz IMU 采样(MPU6050: 加速度 ±16g, 角速度 ±2000dps)
        |
        v
路径 B: 确定性状态机 Fall_Algo_Process()  ← fall_algo.c, 负责"检出"
        |  返回 1 = 确认跌倒
        v
NN 复核: EI_Fall_Classify()  ← 神经网络对最近 3s 数据分类, 负责"否决误报"
        |
        v
两者结合(main_task.c): B 确认 且 NN 不否决 -> 发星闪 0x05 报警
```

- **路径 B(主触发)**:基于跌倒的固定物理特征序列做确定性判定 —— 必经关卡，由它决定"是否检出"。下面第 3~5 节详述。
- **NN(复核否决)**:Edge Impulse 神经网络对最近 3s 数据做一次分类，**只在 normal 置信度 ≥95% 时把路径 B 的报警否决掉**；NN 同意 / 不可用 / 置信度不足 → 一律以路径 B 为准报警。详见第 7 节。
- **触发权属于 B,否决权属于 NN**。两者都同意才报警；NN 高置信反对 B 才能挡住。**保守优先不漏报**。

NN 在 **2026-05-19** 从"无区分力被禁用"复活为"真正生效"(详见第 5 节复盘最后一行 + 第 7 节)。
**当前状态:NN 启用,板上硬真摔 NN 输出 fall=100%。**

## 2. 数据的物理意义 —— 算法的地基

整套算法只用一个传感器(MPU6050)的两类数据:**加速度**和**角速度**。判定为什么这么设计，
全部建立在下面这些物理事实上。看懂这一节，后面四道判据就都是"理所当然"。

### 2.1 加速度计到底测的是什么

加速度计测的**不是"运动有多快地变化"**，而是物理上的"**比力 / 比加速度**" —— 它感受到的
是除重力以外作用在它身上的**支撑力**。

- **静止放着时**:传感器只受重力 + 桌面/支架的支撑力。它读到的是那个支撑力 —— 大小
  `1G`、方向朝上(背离地心)。
- **关键基线**:**只要物体静止不动，无论什么姿态，\|acc\| 恒等于 ≈ 1G。** 这是后面
  所有判据的"零点"。
- 单位 `G`:`1G = 9.8 m/s²` = 地球表面重力加速度。代码里 `acc = sqrt(ax²+ay²+az²)`
  就是三轴合成的"加速度幅值"，静止时 ≈ 1.00G。

### 2.2 失重 —— \|acc\| 跌破 1G 的物理含义(判据 1)

- **自由落体 = 只剩重力、没有支撑力** → 加速度计读 `~0G`。空间站宇航员"飘起来"就是
  这个状态(失重)。
- 人跌倒时，身体在下坠那一刻**失去支撑**，腰部传感器的 \|acc\| 就明显**跌破 1G**。
- 但人摔倒是"翻倒"，不是教科书式的理想自由落体 —— 有肢体扒、有旋转、有部分接触，
  所以 \|acc\| 通常掉到 `0.1 ~ 0.5G`，不会真的到 0。
- `ffmin`(失重段记录到的最低 \|acc\|)= **失重有多彻底**。判据 1 的 `FF_ACC_G=0.75`
  就是规定"\|acc\| 低于 0.75G 即视为失重"。

### 2.3 冲击 —— \|acc\| 骤升的物理含义(判据 2,也是区分"摔"和"蹲"的根本)

撞地 = 身体的下坠速度在**极短时间内被地面强行刹停**。这里有两条物理定律:

- **牛顿第二定律 `F = m·a`**:速度变化越快(刹停时间 Δt 越短)→ 加速度 a 越大 →
  传感器读到的 G 值越高。
- **冲量定理 `F·Δt = Δ(m·v)`**:动量变化 `m·v` 一定时，**刹停时间 Δt 越短、冲击力 F 越大**。

由此得到本算法最重要的一条物理区别:

| 动作 | 减速过程 | Δt | 冲击峰值 |
|------|---------|-----|---------|
| **真实跌倒** | 失控撞地，动量被地面在**几毫秒**内强行归零 | 极小 | **很高**(实测 5~16G) |
| **快速蹲下 / 用力坐下** | 腿部**肌肉在几十~上百毫秒里缓冲减速** | 大得多 | **低**(实测 ≤3G) |

→ 同样是"身体下降然后停住"，**刹停有多硬**完全不同。这就是判据 2
`IMPACT_HARD_G=4.0` 能干净区分"摔倒"和"蹲下"的**物理根本** —— 不靠动作像不像，
靠"撞击是失控的还是肌肉控制的"。

### 2.4 冲击后静止 —— \|acc\| 回到 ~1G 不动的物理含义(判据 3)

- 人摔倒**躺地后**，身体不再产生运动加速度 → 传感器只剩重力，\|acc\| 稳定在 `~1G`
  且基本不变。
- 如果人还在挣扎、翻身、爬起，身体有运动加速度，\|acc\| 会偏离 1G、上下波动。
- 冲击刚结束的约 0.5s 是"**翻滚/沉降期**"(身体回弹、安顿、可能滚动)，这段还在动 ——
  所以判据 3 **跳过这 0.5s**，只统计之后人真正躺定的约 1s。

### 2.5 倾角 —— 重力"方向"变化的物理含义(判据 4)

- 重力永远指向地心。加速度计静止时读到的那个 1G 向量，它的**方向**就告诉你
  "传感器相对竖直方向是什么姿态"。
- 人**直立**(站/坐)时，腰部传感器的重力向量大致沿身体竖轴。
- 人**摔倒躺地**后，身体变水平，重力向量转到了另一个轴上 —— 方向变化约 **90°**。
- 算法比较"事件前直立时"与"冲击后静止时"两个重力向量的**夹角**:
  夹角大 = 躯干从竖直倒成了水平 = 真摔；夹角小 = 躯干还竖着 = 蹲下/坐下/起跳。
- **注意**:\|acc\| 的"大小"区分不了"站着不动"和"躺着不动"(两者都 ≈1G)，
  只有重力的"**方向**"能区分。这正是判据 4 单独存在的物理理由。
- 因为只比较"前后方向变化量"，所以**与传感器装在身上的朝向无关**。

### 2.6 角速度(陀螺仪)

- 陀螺仪测的是"**转动有多快**"，单位 `dps`(度/秒)。
- 跌倒往往伴随身体翻转 → 角速度大(日志里真摔 `gyr_peak` 常 500~1700 dps)。
- 当前算法 v1 **没有把陀螺仪纳入判定**(只在 `[Monitor]` 日志里打印观察)，纯靠
  加速度的"幅值序列 + 方向变化"。陀螺仪可作为后续增强的特征。

### 2.7 采样率与"样本数"

- `200Hz` 采样 = 每 `5ms` 一个样本。文中所有"N 个样本"都能换算成时间:`N × 5ms`。
- 例:`FF_MIN_SAMPLES=14` = 70ms；`STILL_WINDOW=200` = 1s；`IMPACT_SETTLE=100` = 0.5s。

## 3. 如何判断一次真实跌倒 —— 四道判据

真实跌倒有一段固定的物理过程，算法把它拆成**四道关卡，必须依次全部满足**才确认跌倒：

| # | 判据 | 物理含义(详见第 2 节) | 不满足时拦住的是 |
|---|------|---------|----------------|
| 1 | **自由落体** | 人失去支撑下坠，\|acc\| 跌破 1G 持续一小段 | 轻拿轻放、抖动 |
| 2 | **硬冲击** | 失控撞地，\|acc\| 冲击峰值很高 | 快速蹲下、用力坐下(肌肉控制的柔和减速) |
| 3 | **冲击后静止** | 人躺在地上不动，\|acc\| 回到 ~1G 且基本不变 | 剧烈摇晃、摔后立刻爬起 |
| 4 | **倾角倒下** | 躯干由直立变为接近水平(重力方向变 ~90°) | 原地起跳落地(冲击大但人仍直立) |
| 5 | **NN 复核**(辅助否决器) | 对最近 3s 的 \|acc\|/\|gyro\| 序列做一次神经网络分类 | NN 高置信判 normal (≥95%) -> 否决 B 的报警；其余情况一律放行 |

判据 1~4 由路径 B (`fall_algo.c`) 串行判定，全部通过返回 1；
判据 5 由 NN (`ei_fall.cpp::EI_Fall_Classify`) 在 B 返回 1 后被 `main_task.c` 调一次，详见第 7 节、第 8 节。

状态机:`IDLE → FREEFALL → IMPACT_WAIT → POST_IMPACT →（确认/否决）→ IDLE`

```text
IDLE         等待失重。同时持续低通记录"直立时的重力方向"作参考(判据4要用)
  | |acc| < FF_ACC_G
  v
FREEFALL     失重计时。太短(抖动)或太久(异常)都复位
  | 失重结束
  v
IMPACT_WAIT  等冲击。窗口内没等到冲击 -> 复位(只是失重没撞地, 如轻放)
  | |acc| > IMPACT_ACC_G
  v
POST_IMPACT  先跳过 ~0.5s 翻滚沉降期, 再统计 ~1s 的静止情况;
             窗口结束时一次性检查: 静止率 + 冲击峰值 + 倾角
  | 静止率达标 且 冲击够硬 且 倾角够大
  v
确认跌倒(返回 1)
```

## 4. 各判据详解与当前阈值

所有阈值在 `fall_algo.c` 顶部宏定义，按 **200Hz 采样、模块佩戴在腰部** 的真人实测调校。

### 判据 1:自由落体段

| 宏 | 当前值 | 含义 |
|----|-------|------|
| `FF_ACC_G` | `0.75f` | \|acc\| 低于此即视为失重。腰部跌倒是"翻倒"，失重较浅，故取 0.75 而非更低 |
| `FF_MIN_SAMPLES` | `14` | 失重至少持续 14 个样本(~70ms)，滤掉抖动 |
| `FF_MAX_SAMPLES` | `150` | 失重超过 ~750ms 判为异常(非跌倒)，复位 |

### 判据 2:冲击 + 硬冲击

| 宏 | 当前值 | 含义 |
|----|-------|------|
| `IMPACT_ACC_G` | `2.20f` | \|acc\| 高于此 = 检测到"有冲击"，状态机进入 POST_IMPACT |
| `IMPACT_WINDOW` | `200` | 失重结束后 200 样本(~1s)内必须出现冲击，否则复位 |
| `IMPACT_HARD_G` | `4.0f` | **主判据**:冲击峰值必须 ≥ 4.0G 才算跌倒 |

> 为什么要分两个冲击阈值:`IMPACT_ACC_G`(2.2G)只用来让状态机往下走；
> `IMPACT_HARD_G`(4.0G)是确认时的硬门槛。物理依据见 2.3 —— 实测快速蹲下/用力坐下
> 的冲击峰值 ≤3.1G(肌肉控制的柔和减速)，真实跌倒 ≥5.3G(失控撞地)，4.0G 落在两者中间。

### 判据 3:冲击后静止

| 宏 | 当前值 | 含义 |
|----|-------|------|
| `IMPACT_SETTLE` | `100` | 冲击后 100 样本(~0.5s)是翻滚/沉降期，**不计入**静止统计 |
| `STILL_WINDOW` | `200` | 跳过沉降期后，再观察 200 样本(~1s)的静止情况 |
| `STILL_LOW_G` / `STILL_HIGH_G` | `0.60f` / `1.40f` | "静止样本"判定:\|acc\| 落在此区间(静止时应 ≈1G) |
| `STILL_MIN_PCT` | `50` | 静止窗口内静止样本占比 ≥ 50% 即判为"躺地不动" |

> 关键点:沉降期跳过。冲击瞬间会翻滚/沉降，把这段算进静止统计会让静止率虚低。
> 改为"冲击后先跳 0.5s，再统计接下来 1s"，要求人在冲击后约 1.5s 内基本不动。

### 判据 4:倾角(区分跌倒 vs 蹲下/起跳)

| 宏 | 当前值 | 含义 |
|----|-------|------|
| `TILT_DEG_MIN` | `45` | 冲击前后"重力方向夹角" ≥ 45° 才算躯干倒下 |
| `GREF_ALPHA` | `0.02f` | IDLE 静止时，低通更新"直立重力方向"参考的系数 |
| `GREF_STILL_LO/HI` | `0.85f` / `1.15f` | 只在 \|acc\|≈1G 时更新方向参考 |

原理见 2.5:跌倒后人躺地、躯干≈水平；坐下/蹲下后躯干仍≈直立。算法在 IDLE 持续记录
"直立时的重力方向"，冲击后再取"静止时的重力方向"，两者夹角大 = 躯干倒了。
**只看前后变化量，与传感器安装方向无关。**

> 倾角是**辅助**判据(主力是硬冲击)。实测真实跌倒 tilt ≥73°，取 45° 留足余量；
> 它主要用来挡"原地起跳落地"这类冲击大但人仍直立的动作。

### 判据 5:NN 复核否决 (`main_task.c`)

| 宏 | 当前值 | 含义 |
|----|-------|------|
| `NN_VETO_NORMAL_PCT` | `95` | 路径 B 触发后,只有 NN 以 ≥95% 置信度判为 `normal` 才否决本次报警 |

> 阈值 95 的依据(2026-05-19 实测):板上硬真摔(11G/15G) NN 输出 `fall=100% normal=0%`,
> 偏软的真摔(5G) `fall≈50% normal≈50%` —— 真摔的 `normal%` 远低于 95,**95 永远不会误杀真摔**;
> 而当路径 B 因抖动/特殊动作触发、NN 高置信判 normal 时,刚好挡掉。
> 这是"宁错放、不漏报"的保守阈值。

### 其它(`main_task.c`)

| 宏 | 当前值 | 含义 |
|----|-------|------|
| `FALL_DETECT_COOLDOWN_MS` | `3000` | 报警后 3s 冷却,避免一次跌倒后续抖动二次触发(序列检测器每次跌倒只确认一次,故无需长冷却) |
| `WS2812B_ALERT_HOLD_MS` | `10000` | 报警后板 A 端 WS2812B 红色闪烁持续 10s |
| `FALL_ALERT_PAYLOAD` | `0x05` | 经星闪发给板 B 的跌倒信号字节 |

## 5. 调参复盘 —— 算法是怎么一步步调出来的

| 阶段 | 现象 / 问题 | 根因 | 解决 |
|------|-----------|------|------|
| 初版 | 真人佩戴摔倒**漏报** | ① 失重要求 24 样本(120ms)太严，真实跌倒失重段偏短；② 静止窗口把冲击瞬间的翻滚也算进去，静止率虚低被否决 | `FF_ACC_G` 0.65→0.75、`FF_MIN_SAMPLES` 24→14、`IMPACT_WINDOW` 100→200、新增 `IMPACT_SETTLE` 跳过沉降期、`STILL_WINDOW` 240→200、静止带放宽、`STILL_MIN_PCT` 70→50 |
| 加判据4 | 真摔能报了，但**立马坐下也报警** | 坐下也有"失重+冲击+静止"三段 | 新增**倾角判据**:对比冲击前后重力方向夹角。坐下躯干不倾(实测 tilt 9~14°)被挡住 |
| 数据定阈值 | **快速蹲下仍误报** | 蹲下时躯干前倾，tilt 能到 60~91°，与真摔重叠，倾角分不开 | 加 `impact`/`ffmin` 实测打印，做带标签对照测试 |
| 加硬冲击判据 | 实测:蹲下冲击 ≤3.05G、真摔 ≥5.3G，干净分界 | 蹲下是肌肉控制的柔和减速、真摔是失控撞地(物理见 2.3) | 新增**硬冲击判据** `IMPACT_HARD_G=4.0`(主判据)；`TILT_DEG_MIN` 降回 45 作辅助 |
| 修 NN bug | 一次真摔被 `[Hybrid] NN veto` 吞掉 | NN 把真摔判成 `normal=80%`，正好触 80 的否决线 | `NN_VETO_NORMAL_PCT` 80→101，实质禁用 NN 否决 |
| **NN 复活 (2026-05-19)** | 旧 NN 学到"朝向捷径",真摔 NN 输出 fall=0% | 录 fall/normal 时传感器朝向不一致 → 模型靠朝向区分而非物理 | 改用**朝向无关的 2 通道幅值特征** `|acc|`/`|gyro|`(`make_features.py`);EI 里 DSP 块从 Raw 改 **Flatten**(消除"冲击在第几位"敏感);重训 v4 上板验证硬真摔 NN 输出 `fall=100%`,`NN_VETO_NORMAL_PCT` 101→**95** 启用 NN 否决 |

**带标签实测数据**(最终定阈值的依据):

| 动作 | tilt | impact | ffmin |
|------|------|--------|-------|
| 快速蹲下 | 61~91° | **2.32 / 2.68 / 3.05G** | 0.05~0.13 |
| 真实跌倒 | 73~112° | **5.30 / 11.57 / 15.62 / 16.05G** | 0.21~0.71 |

结论:`impact`(冲击峰值)是最干净的分界 —— 物理上对应"失控撞地 vs 肌肉缓冲"(见 2.3)；
`tilt` 会重叠、`ffmin` 甚至反向，故 `impact` 作主判据。

## 6. 怎么看串口日志

确认跌倒(四项齐全):
```text
[Fall] freefall NN samples, waiting for impact...
[Fall] impact detected, checking stillness...
[Fall] CONFIRMED (impact 11.57G, tilt 88 deg, ffmin 0.64G, still 94%)
[Alert] Fall Detected. Sending SOS now...
```

四个实测量的物理含义:`impact`=冲击峰值(撞地多猛)、`tilt`=躯干倒了多少度、
`ffmin`=失重最低点(失重多彻底)、`still`=冲击后静止样本占比。

各种否决(每条都打印这四个值，便于继续微调):
```text
[Fall] rejected: still NN% ...                         冲击后没躺稳(摇晃/爬起)
[Fall] rejected: soft impact, sit/squat? (impact 2.xG ...)  冲击太柔, 疑似蹲下/坐下
[Fall] rejected: upright, jump? (tilt NN deg ...)       冲击够硬但人仍直立, 疑似起跳落地
```

`[Monitor] B=<状态> acc=...~...G gyr_peak=... ` 每秒打印状态机当前状态与本秒 IMU 范围。

## 7. NN(神经网络)复核器 —— 已生效

**状态:启用,作为路径 B 的否决器(2026-05-19 后)。**
代码:`src/ei_fall.cpp`。模型项目:Edge Impulse `fall_ws63_waist` (project_id=999999),已编译进固件。

### 7.1 输入特征:2 通道朝向无关幅值(关键设计)

不喂 6 轴原始值 `(ax,ay,az,gx,gy,gz)`,只喂两路幅值:

```c
acc_mag = sqrtf(ax*ax + ay*ay + az*az) * 1000   // milli-g
gyr_mag = sqrtf(gx*gx + gy*gy + gz*gz) * 100    // centi-dps
```

**为什么用幅值而非 6 轴**:旧 6 轴模型 EI 测 97%、板上真摔 `fall=0%` —— 根因是模型学到了
"**朝向捷径**":录 fall 时传感器朝向一致(重力在 +Z)、录 normal 时朝向散乱,模型直接靠
"传感器现在哪个轴朝下"区分,而不是跌倒物理。改用 `|acc|`/`|gyro|` 幅值后,**与佩戴朝向完全无关**
(与路径 B 的倾角判据同理 —— 都只看变化量,不看绝对朝向)。

量纲换算 `×1000` `×100` 必须与训练数据(`ws63-edge-ai-guide/tools/make_features.py` 生成的 CSV)
**逐位对齐**,否则会重蹈早期 SisFall 那次"训练/部署量纲不一致"的覆辙。

### 7.2 窗口构造:600 样本环形缓冲 = 3 秒

```text
每个 200Hz 样本 ──► EI_Fall_Push(ax..gz)
                        │ 就地算 |acc|/|gyro| 两通道
                        ▼
       g_ring[600 样本 × 2 通道] (环形,头指针 g_ring_head)
       始终持有最近 3.0s 数据

路径 B 触发 ──► EI_Fall_Classify()
                        │ 两段 memcpy:[head, 末尾) 接 [0, head)
                        ▼
       g_window[600×2] (时间有序的连续窗口)
                        ▼
            run_classifier(handle, signal, &result)
                        ▼
              fall_prob / normal_prob (0..1)
```

- `EI_CLASSIFIER_FREQUENCY = 200`、`EI_CLASSIFIER_INTERVAL_MS = 5`(EI 训练时也是 200Hz)。
- 缓冲未满(冷启不到 3s)时跳过 NN、返回 `valid=false`,主任务按"NN 不可用"处理(放行报警)。
- `run_classifier` 单次耗时 ~100ms 级,期间采样任务(优先级更高)继续把样本压入 IMU 队列,**不掉节拍**。

### 7.3 EI DSP 块用 Flatten,不用 Raw(关键设计)

EI 项目里 DSP 块选 **Flatten**(对窗口求位置无关的统计量,NN 输入降到 14 维),而不是 Raw。

**为什么**:Raw + 逐位置 StandardScaler 让模型对"冲击峰值在样本第几位"敏感 ——
训练片段把冲击切在样本 240、板上部署窗口冲击常落在样本 300 → EI 测 95%、板上真摔 `fall=10%`。
改 Flatten 后位置不再重要,板上真摔 `fall=100%`。

### 7.4 推理结果如何参与判定

```c
ei_fall_result_t nn = EI_Fall_Classify();   // {valid, fall_percent, normal_percent}

if (status_from_path_B == 1) {              // 仅在 B 触发时才调一次 NN
    if (nn.valid && nn.normal_percent >= NN_VETO_NORMAL_PCT /*=95*/) {
        // NN 高置信反对 → 否决本次报警,不进冷却,后续真跌倒仍可立即触发
        log("[Hybrid] B triggered, NN veto: alert suppressed");
    } else {
        // NN 同意 / 不可用 / 置信度不足 → 一律以路径 B 为准报警
        log(nn.valid ? "[Hybrid] B+NN agree" : "[Hybrid] NN unavailable, trusting path B");
        send_alert(0x05);
    }
}
```

三种分支:

| NN 结果 | 处理 |
|---------|------|
| `valid=true` 且 `normal_percent >= 95` | **否决** 本次报警,不发星闪,不进冷却 |
| `valid=true` 且 `normal_percent <  95` | 报警,日志 `[Hybrid] B+NN agree (fall=%d%% normal=%d%%)` |
| `valid=false` (冷启 3s 内,或 `run_classifier` 失败) | 报警,日志 `[Hybrid] NN unavailable, trusting path B` |

### 7.5 当前实测(2026-05-19 验证通过)

| 动作 | 路径 B | NN 输出 | 最终 |
|------|--------|---------|------|
| 硬真摔(11G/15G) | B = CONFIRMED | `fall=100% normal=0%` | 报警,`[Hybrid] B+NN agree` |
| 偏软的真摔(5G) | B = CONFIRMED | `fall≈50% normal≈50%` | 报警(normal<95) |
| 快速蹲下/坐下 | B = rejected (soft impact) | NN 不调用 | 不报警 |
| 原地起跳落地 | B = rejected (upright) | NN 不调用 | 不报警 |

**NN 永远不会误杀真摔**:真摔 NN `normal%` 最高 ≈50,远低于 95。
**NN 能挡误报**:若哪天路径 B 出现极特殊触发,NN 高置信判 normal 即可拦截。

### 7.6 实现要点(`ei_fall.cpp`)

- **C++ 全局构造不可靠**:WS63 启动不保证执行 C++ 全局构造函数,不能直接用 EI 生成的
  `ei_default_impulse`。改用 `placement new` 在静态存储 `g_handle_storage` 上显式构造
  `ei_impulse_handle_t`。
- **`-Wnarrowing` 局部抑制**:EI 生成的 `model_variables.h` 个别大整数标量没写成浮点字面量,
  在 `const float[]` 初始化里被 GCC 判 narrowing、被 `-Werror` 升成错误。用
  `#pragma GCC diagnostic ignored "-Wnarrowing"` 包住三个 EI include 解决。
- **静态内存池 64KB**:`run_classifier` 通过 `ei_malloc` 申请 DSP 中间矩阵(~14KB)+ 小块。
  改走 `LOS_MemInit` 的静态池(`ei_porting_ws63.cpp`)而非系统堆 —— 一次性框定 NN 的 RAM 占用,
  消除早期 -22 分配失败。
- **EI 平台移植排除**:WS63 toolchain 定义 `__unix__`,EI 的 `porting/posix/*.cpp` 不带 weak
  的 `ei_read_timer_*` 会与我们的 `ei_porting_ws63.cpp` 起符号冲突 —— CMakeLists 把整批
  `arduino/posix/...` 排除。

排查记录详见 `docs/04-TinyML模型/EdgeImpulse_NN调试实录_2026-05-19.md` 与
`EdgeImpulse_模型集成与B+NN混合判定_2026-05-18.md`。

## 8. 混合判定主循环 —— `main_task.c` 完整流程

每个 200Hz 样本走一遍下面的完整链路。`Fall_Detect_Task_Body` 的核心循环:

```c
while (1) {
    imu_sample_t sample;
    osMessageQueueGet(g_imu_queue, &sample, ..., osWaitForever);   // 等采样任务推 IMU

    // (A) 始终喂 NN 环形缓冲,使其持有最近 3s 数据(供 B 触发时复核)
    EI_Fall_Push(sample.ax, sample.ay, sample.az,
                 sample.gx, sample.gy, sample.gz);

    // (B) 监控统计:本秒内 |acc| 范围、|gyro| 峰值,供 [Monitor] 日志
    float acc_mag = sqrtf(ax*ax + ay*ay + az*az);
    float gyr_mag = sqrtf(gx*gx + gy*gy + gz*gz);
    update_mon(acc_mag, gyr_mag);

    // (C) 路径 B 状态机:四道判据,返回 1 = 确认跌倒
    int status = Fall_Algo_Process(ax, ay, az, gx, gy, gz);
    uint64_t now_ms = uapi_systick_get_ms();

    // (D) WS2812B 闪烁保持期到点 → 关红色灯
    if (g_ws2812b_alert_active && now_ms >= ws2812b_alert_until) {
        g_ws2812b_alert_active = false;
    }

    if (fall_cooldown_start != 0 &&
        (now_ms - fall_cooldown_start) < FALL_DETECT_COOLDOWN_MS /*3s*/) {
        // (E) 冷却中:跳过判定,周期打印 "Cooldown: Ns left"
        continue_with_cooldown_log();
    } else if (status == 1) {
        // (F) 路径 B 确认 → NN 复核
        ei_fall_result_t nn = EI_Fall_Classify();

        if (nn.valid && nn.normal_percent >= NN_VETO_NORMAL_PCT /*95*/) {
            // (F1) NN 高置信反对 → 否决,不报警、不进冷却
            log("[Hybrid] B triggered, NN veto (normal=%d%% fall=%d%%): alert suppressed",
                nn.normal_percent, nn.fall_percent);
        } else {
            // (F2/F3) NN 同意 / 不可用 → 报警
            if (nn.valid)
                log("[Hybrid] B+NN agree (fall=%d%% normal=%d%%)", ...);
            else
                log("[Hybrid] NN unavailable, trusting path B");

            log("[Alert] Fall Detected. Sending SOS now...");

            // (G) 发星闪(或 BLE)给板 B
            #ifdef CONFIG_FALL_DETECT_USE_SLE
                uint8_t payload = FALL_ALERT_PAYLOAD;  // 0x05
                sle_send_fall_alert(&payload, 1);
            #else
                Ble_Send_Fall_Alert(FALL_ALERT_PAYLOAD);
            #endif

            // (H) 本机 WS2812B 红闪 10s + 进入 3s 报警冷却
            g_ws2812b_alert_active = true;
            ws2812b_alert_until    = now_ms + WS2812B_ALERT_HOLD_MS;  // 10s
            fall_cooldown_start    = now_ms;                          // 3s 冷却起点
        }
    }

    // (I) 每 200 样本(≈1s)打印一次 [Monitor]:B 状态 / acc 范围 / gyr 峰 / 队列水位 / 丢样数
    if (++processed >= MONITOR_INTERVAL /*200*/) {
        processed = 0;
        log("[Monitor] B=%s acc=%.2f~%.2fG gyr_peak=%d dps q=%u/%u drops=%u", ...);
        reset_mon();
    }
}
```

**几个关键设计在代码里的体现**:

| 设计 | 体现 |
|------|------|
| NN 始终保持最近 3s 缓冲 | (A) `EI_Fall_Push` 每样本必调,与 B 触发与否无关 |
| 路径 B 是必经主触发器 | (C/F) 只有 `status==1` 才会启用 NN 复核;NN 不会绕过 B 单独报警 |
| NN 只能否决、不能"额外触发" | (F1) `valid && normal>=95` 才否决,其余路径全部走 (F2/F3) 报警 |
| 否决不进冷却 | (F1) 不更新 `fall_cooldown_start` → 后续真跌倒立即能触发 |
| 报警后 3s 冷却 + 10s 灯保 | (H) `fall_cooldown_start = now_ms;ws2812b_alert_until = now_ms+10s` |
| 推理期间不掉采样节拍 | 采样任务 `osPriorityAboveNormal` 优先级更高,`run_classifier` 期间样本继续入队 |

**冷启 3s 的窗口未满期间**:`EI_Fall_Classify` 直接返回 `valid=false`,主循环走 (F3) ——
**NN 不可用时一律放行报警,绝不漏报**。

## 9. 参数速查与调参建议

全部阈值在 `fall_algo.c` 顶部宏 + `main_task.c:37` 的 `NN_VETO_NORMAL_PCT`。现场微调时盯串口实测值:

- **真摔漏报**:看 `[Fall]` 卡在哪一关 —— 卡判据1 调 `FF_MIN_SAMPLES`/`FF_ACC_G`;
  卡判据2 看 `impact` 实测值,体弱者真摔可能 <5G,则下调 `IMPACT_HARD_G`;
  卡判据3 调 `STILL_MIN_PCT`;卡判据4 调 `TILT_DEG_MIN`。
  若日志出现 `[Hybrid] NN veto` → 真摔被 NN 否决了,上调 `NN_VETO_NORMAL_PCT` (但记忆里真摔 normal% 最高 50,正常不会出现)。
- **误报**(蹲下/坐下/日常动作):看误报事件的 `impact` —— 通常 <4G,说明硬冲击判据该挡住,
  检查是否被调松;必要时上调 `IMPACT_HARD_G`。
  若误报频繁但都是 `[Hybrid] B+NN agree`,说明 NN 对该动作也判 fall,需要补该类动作的 normal 样本重训。
- 改完需**重新编译、烧录板 A**。
