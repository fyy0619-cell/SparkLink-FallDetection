# 功耗分析与电源管理

## 各模块功耗估算

| 模块 | 典型电流 | 峰值电流 |
|------|----------|----------|
| WS63主控（运行） | 80mA | 150mA |
| MPU6050 | 3.9mA | 5mA |
| SLE协议栈（发射） | 30mA | 80mA |
| 毫米波雷达 | 200mA | 500mA |
| **合计（并行）** | **~315mA** | **~735mA** |

## 关键问题：SLE与雷达并行时的供电崩溃

**现象**：SLE协议栈与毫米波雷达同时工作时，系统随机崩溃/重启。

**根本原因**：峰值电流超出MH-CD42的输出能力（额定1A），导致电压跌落，触发MCU欠压复位。

### 解决方案一：时序错开（推荐）

```c
// 雷达扫描与SLE发送错开时间
void radar_scan_task(void)
{
    radar_start();
    osDelay(50);        // 等雷达峰值电流过去
    sle_send_result();  // 再启动SLE发送
}
```

### 解决方案二：硬件加固

在电源输入端并联大电容缓冲峰值电流：
- 4.7μF ~ 100μF 铝电解电容（低ESR）并联在5V输入
- 100nF陶瓷电容去耦

### 解决方案三：升级供电

- 将MH-CD42更换为输出能力2A的模块
- 或使用18650电池直接供电（内阻低，峰值电流承受能力强）


## LiteOS低功耗配置

```c
// 在不采集数据时，让CPU进入低功耗模式
LOS_SysTickDisable();       // 关闭系统滴答
// 唤醒条件：MPU6050数据就绪中断
```

> **注意**：开启低功耗模式后，确认调试串口不会因为时钟变化而乱码。
