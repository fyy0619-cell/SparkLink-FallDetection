## 第二部分:📋 演示当天 5 步开机清单

按顺序勾,每步搞定再下一步。

### ☐ Step 1:开手机热点 + 笔记本接入(30 秒)

- 手机:**设置 → 个人热点 → 打开**
  - SSID: `OPPO Find X9s Pro` ← **必须就是这个名字**(笔记本静态 IP 只对这个 SSID 生效)
  - 密码: `yyfu0619` ← 板 B 固件硬编码,改了就连不上
  - 协议: 2.4G(注意不是 5G)
- 笔记本: 点 WiFi 图标 → 选 `OPPO Find X9s Pro` → 连接

### ☐ Step 2:验证笔记本 IP = `10.189.231.184`(10 秒)

**两种方式任选其一:**

**A. 终端方式**(推荐,顺手测好):
```bash
ipconfig | findstr IPv4
```
应该看到一行 `10.189.231.184`。

**B. 鼠标方式**(不开终端):
- Windows 设置 → 网络 → WLAN → 点 `OPPO Find X9s Pro` → 滚到下面看 `IPv4 地址`
- 应该显示 `10.189.231.184`

**如果不是 `10.189.231.184`** → 见 [§ 出错怎么办](#-出错怎么办)。

### ☐ Step 3:双击 .bat 启动 backend(10 秒)

**双击** `D:\fbb_ws63\SparkLink-FallDetection\tools\start_backend.bat`

> 💡 演示常用:**右键 .bat → 发送到 → 桌面快捷方式**,下次桌面双击启动,连资源管理器都不用打开。

弹出黑窗口,应该看到:
```
================================================================
 Fall Alert Backend - PushPlus
================================================================
 Working dir: D:\fbb_ws63\SparkLink-FallDetection\tools

Notify provider: pushplus, dry_run=False
Rate limit: 60s
Contacts: ['+8613800138000']
Listening on http://0.0.0.0:8080/api/fall-alert
```

**别关这个窗口**——后面 backend 会在这里打实时日志。演示时投到大屏幕也可以,跌倒事件 + PushPlus 响应都会滚出来,**视觉效果非常好**。

> 💡 老派终端方式(等效,不用 .bat):
> ```bash
> cd D:/fbb_ws63/SparkLink-FallDetection/tools
> python fall_alert_backend_demo.py
> ```
> (Python 启动时自带 `.env` 加载器,**不需要** `source` 或 `set -a`。)

### ☐ Step 4:板 A + 板 B 接电(15 秒)

- 板 A 接 Type-C 电(笔记本 USB / 充电宝都行)
- 板 B 接 Type-C 电
- **(强烈推荐)** 各开一个串口工具(MobaXterm / VS Code Serial Monitor / Putty),波特率 `115200`,看板 A + 板 B 的实时日志。演示时跟 backend 窗口一起投影 = 三个窗口让评委看到完整链路在跑

### ☐ Step 5:等就绪(约 30 秒)—— 别急着摔!

**两种就绪检测方式:**

#### A. 看串口(推荐,精准)

**板 B 串口必须同时出现这两块**:

▸ SLE 已连:
```
[CLIENT] Connected to Server! conn_id: 0
[CLIENT] MTU exchange done: mtu=512, status=0x0
[CLIENT] Matched fall service UUID=0xabcd ...
```

▸ WiFi 已就绪:
```
[FALL_GW] Wi-Fi connected.
[FALL_GW] DHCP success, ip=10.189.231.xxx
[FALL_GW] gateway ready
```

**两块都齐才能摔**。

#### B. 不看串口(应急,粗略)

如果没开串口/串口太多看不过来,**摇一下板 A**:
- 板 A 灯带颜色应该有变化(NN/IMU 在工作的表现)
- **再等 30 秒后再开始摔**(给 WiFi 状态机充足缓冲时间)

> ⚠️ 千万**不要 SLE 一通就立刻摔**——SLE 5 秒内就连上,但 WiFi 扫描+DHCP 通常要 15~30 秒。
> 那时摔虽然蜂鸣器/灯会响(SLE 已通),但 HTTP 路径没就绪,**微信会收不到**。这就是这次踩过的经典坑。

## ✅ 摔!

抓板 A 模拟一次真实跌倒(或自由落体到防摔垫;真人佩戴摔需要防护)。

期望全链路现象(按时间顺序):

| T+ | 在哪里 | 现象 |
|----|--------|------|
| 0 | **板 A 串口** | `[Fall] CONFIRMED (impact 11.57G, tilt 88 deg, ...)` + `[Hybrid] B+NN agree (fall=100%)` |
| 200ms | **板 A 串口 + 物理** | `[SLE Server] Fall alert sent successfully!` + 板 A 上 LED 红闪 |
| 230ms | **板 B 串口** | `[CLIENT] Notification: data[0]=0x05` + `[CLIENT ALERT] SOS RECEIVED!` |
| 230ms | **板 B 物理** | **蜂鸣器持续响** + 灯带红色 5Hz 快闪 + 普通 LED 常亮 |
| 500ms | **板 B 串口** | `[FALL_GW] HTTP POST /api/fall-alert → 200 OK` |
| 1s | **backend 黑窗口** | `[FALL ALERT]` JSON + `[NOTIFY] PushPlus response: {"code":200,...}` |
| 1.5~3s | **你的微信** | "PushPlus推送加" 公众号推送 "## 跌倒报警" 卡片 ✅ |

## ⚠️ 演示中段如果要重复摔

backend **默认 60 秒频限**(防止一次跌倒重复推送)。两次摔之间需要间隔 > 1 分钟。

若想现场连摔展示,**演示开始前**改 `.env`:
```
FALL_RATE_LIMIT_SECONDS=5
```
然后重启 backend(关掉黑窗口再双击 .bat)。

> 演示完后**不必改回 60**,5 秒频限对日常也够用。

## ❌ 出错怎么办

### ☒ Step 2 IP 不对(不显示 `10.189.231.184`)

**A. 笔记本不在 OPPO 热点上**
- 看 WiFi 图标,接的是不是 `OPPO Find X9s Pro`,接错的重连

**B. 接对了但 IP 是 DHCP 分的别的(不是 .184)**
- 静态 IP 设置被改回"自动 (DHCP)"了
- Windows 设置 → 网络 → WLAN → 点 `OPPO Find X9s Pro` → "IP 分配" → 编辑 → 改回"手动" + 填 `10.189.231.184`
- 详细见 [`热点IP变动应对流程.md` §2.1](热点IP变动应对流程.md)

**C. OPPO 热点 DHCP 网段变了(罕见,手机重大更新后可能)**
- 接受新 IP → 用脚本自动改板 B 固件 + 重编 + 烧:
  ```bash
  cd D:/fbb_ws63/SparkLink-FallDetection/tools
  python update_gateway_ip.py
  ```
- 详细见 [`热点IP变动应对流程.md` §3](热点IP变动应对流程.md)

### ☒ Step 3 backend 起不来 / .bat 一闪就消失

**.bat 闪退**——双击后黑窗口直接关闭看不到错:
- 改用法:**先打开 cmd 窗口**(开始菜单搜 cmd) → 然后把 `start_backend.bat` 拖到 cmd 窗口 → 回车 → 错误信息留在 cmd 里不会消失

**端口被占用**:
```bash
netstat -ano | findstr :8080.*LISTEN
# 如果有 pid,关掉占 8080 的进程,再双击 .bat
```

**Python 报缺包**:
```bash
pip install setuptools kconfiglib windows-curses jinja2
```

**PUSHPLUS_TOKEN is empty 错误**:
- 打开 `tools\fall_alert_backend.env`,确认 `PUSHPLUS_TOKEN=` 后面真的有 token(32 位字符)
- 若 .env 文件不存在,从 `.env.example` 拷一份再填

### ☒ Step 5 等了很久 SLE 不连上

- 板 A 串口看是否 `[Sample] 200Hz hardware-timed sampling started` —— 没的话板 A 自身有问题(可能 MPU6050 没接好)
- 板 B 串口看是否 `[CLIENT SCAN] Saw MAC: 11:22:33:44:55:66` —— 没的话板 B 看不到板 A 广播
- 两板距离 < 10 米且无金属遮挡
- 板 A 重启一次(SLE 偶发握手慢)

### ☒ 摔了蜂鸣器响 + 灯红闪,但微信不收到

**这是经典症状**,本仓库已经踩过这个坑。直接看专题:
[`热点IP变动应对流程.md` §0](热点IP变动应对流程.md) — 6 段链路图 + 5 种症状速查表。

最常见根因(按概率排序):
1. backend 没起 → 看任务栏有没有那个黑窗口
2. backend 在 `127.0.0.1:8080` 而不是 `0.0.0.0:8080` → 重启 .bat
3. 笔记本 IP 漂走了 → 回 Step 2 验证

## 哲学总结

| | 做了一次就不用再做的 | 每次演示都要做的 |
|---|---|---|
| **PushPlus** | 注册、关注公众号、复制 token、填 `.env` | (无) |
| **网络** | 设笔记本 WLAN 静态 IP = 10.189.231.184 | 开手机热点 + 笔记本接入 |
| **固件** | 编译、烧板 A、烧板 B | (无,直接上电) |
| **后端** | 写 Python、装依赖、配 `.env`、写 .bat | **双击 .bat** |
| **检查** | (无) | Step 2 验 IP + Step 5 等 `gateway ready` |
| **演示** | (无) | 摔板 A |

"做一次的"都已经存好——硬盘里 / 板子 flash 里 / 微信公众号订阅里——**永远不会因为关机/重启而消失**。
"每次要做的"全是物理动作(开热点 / 上电)或一次鼠标双击。
