## 出错怎么办

### ☒ Step 2 IP 不对(`ipconfig` 不显示 `10.189.231.184`)

**A. 笔记本不在 OPPO 热点上**
- 看 WiFi 图标,接的是不是 `OPPO Find X9s Pro`,接错的话重连

**B. 接对了但 IP 是 DHCP 分的别的(不是 .184)**
- 说明静态 IP 设置被改回了"自动 (DHCP)"
- 去 Windows: 设置 → 网络 → WLAN → 点 `OPPO Find X9s Pro` → "IP 分配" → 编辑 → 改回手动 + 填 184
- 详细步骤见 [`热点IP变动应对流程.md` §2.1](热点IP变动应对流程.md)

**C. OPPO 热点 DHCP 网段变了(罕见,手机重大更新后可能)**
- 接受新 IP → 用脚本一键改板B 固件 + 重编 + 烧
- ```bash
  cd D:/fbb_ws63/SparkLink-FallDetection/tools
  python update_gateway_ip.py
  ```
- 详细见 [`热点IP变动应对流程.md` §3](热点IP变动应对流程.md)

### ☒ Step 3 backend 起不来

**端口被占用**:
```bash
netstat -ano | grep :8080
# 杀掉占 8080 的进程,或改 backend --port 18081
```

**Python 报缺包**:
```bash
pip install setuptools kconfiglib windows-curses jinja2  # 一次性补齐
```

### ☒ Step 5 等了很久 SLE 不连上

- 板 A 看是否 `[Sample] 200Hz hardware-timed sampling started`
- 板 B 看是否 `[CLIENT SCAN] Saw MAC: 11:22:33:44:55:66`
- 两板距离 < 10 米
- 板 A 重启一次(SLE 偶发握手慢)

### ☒ 摔了蜂鸣器响但微信不收到

参见专题:[`热点IP变动应对流程.md` §0](热点IP变动应对流程.md) —— 这是经典症状,本仓库已经踩过这个坑。

## 一些"哲学"

| | 做了一次就不用再做的 | 每次演示都要做的 |
|---|---|---|
| **PushPlus** | 注册、关注公众号、复制 token、填 `.env` | (无)|
| **网络** | 设笔记本静态 IP | 开手机热点 + 笔记本接入 |
| **固件** | 编译、烧板 A、烧板 B | (无,直接上电)|
| **后端** | 写 Python、装依赖、配 `.env` | 一行 bash 启动它 |
| **检查** | (无) | `ipconfig` 看 IP + 等板 B `gateway ready` |

"做一次的"已经存在你硬盘里 / 板子 flash 里 / 微信公众号订阅里,**永远不会因为关掉电脑而消失**。
"每次要做的"全都不超过 1 行命令或 1 个手动操作。
