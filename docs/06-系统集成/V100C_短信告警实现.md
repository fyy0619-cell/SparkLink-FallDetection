# V100C / Air780EHV 短信告警实现

> 在已跑通「跌倒 → 打电话」的基础上（见 [V100C/Air780EHV 串口拨号调试](V100C_Air780EHV_UART_call_debug_2026-05-13.md)），新增「跌倒 → 发短信给指定号码」。打电话和发短信可独立开关，默认两者都发。

---

## 1. 模块能力说明

银尔达 V100C 内部是 Air780EHV（4G Cat.1 模组），短信是其基础能力：

- 打电话用 LuatOS 的 `cc` 库（`cc.dial`）—— 已验证。
- 发短信用 LuatOS 的 `sms` 库（`sms.send`）—— 本次新增。

`sms` 库由固件提供。一般支持 `cc` 的固件也带 `sms`，但稳妥起见，先用最小脚本 `tools/v100c_min_sms_test.lua` 单独验证（思路与当初验证打电话的 `v100c_min_call_test.lua` 一致）。

---

## 2. 数据链路

复用打电话的 UART JSON 通道，新增一种 `cmd`：

```text
Board B 跌倒事件
  -> fall_alert_4g_dtu 任务
  -> UART1 依次发出两行 JSON：
       {"cmd":"sms","phone":"<TARGET_PHONE>","text":"...","device":"...","event_count":N}
       {"cmd":"call","phone":"<TARGET_PHONE>","device":"...","payload":5,"event_count":N,"event":"fall_alert"}
  -> V100C lua 任务逐行 json.decode
  -> cmd=="sms"  -> sms.send(phone, text)
  -> cmd=="call" -> cc.dial(0, phone)
```

先发短信、隔约 500ms 再发拨号指令：让短信先进入发送队列，再用语音呼叫占用模组。

## 3. WS63 侧（Board B）

### 3.1 配置 `inc/fall_alert_4g_dtu_config.h`

```c
/* 打电话 / 发短信 可独立开关，都发往 FALL_ALERT_4G_DTU_PHONE */
#define FALL_ALERT_4G_DTU_CALL_ENABLED   1
#define FALL_ALERT_4G_DTU_SMS_ENABLED    1

/* 短信正文：不要含双引号(")或反斜杠(\)，否则破坏 JSON */
#define FALL_ALERT_4G_DTU_SMS_TEXT \
    "Fall detected. Please check on the elder immediately."
```

目标号码仍是 `FALL_ALERT_4G_DTU_PHONE`，即「指定的电话」。改完需重新编译并烧录 Board B。

### 3.2 实现 `src/fall_alert_4g_dtu.c`

- 新增 `fall_alert_4g_dtu_send_sms_json()`，拼出 `cmd:"sms"` 的 JSON 并经 UART1 写出。
- DTU 任务在一次告警里：先发短信 JSON，`osal_msleep(500)`，再发拨号 JSON。
- 两路只要有一路写成功就算本次告警已处理，并进入 `FALL_ALERT_4G_DTU_COOLDOWN_MS`（默认 60s）冷却，避免重复呼叫/重复短信。

串口可见日志：

```text
[FALL_DTU] JSON cmd=sms  sent to V100C: count=1, len=..., phone=configured.
[FALL_DTU] JSON cmd=call sent to V100C: payload=0x05, count=1, len=..., phone=configured.
```

## 4. V100C 侧（lua 任务）

`tools/v100c_uart_call_task.lua` / `tools/V100C_PASTE_THIS_TO_TASK1.lua` 已加入短信处理：

```lua
local function sendSms(phone, text)
    if not phone or phone == "" then return false end
    if not text or text == "" then text = "Fall detected. Please check now." end
    if type(sms) ~= "table" or type(sms.send) ~= "function" then
        log.info(tname, "sms lib not available in this firmware")
        return false
    end
    local ok = sms.send(phone, text)
    log.info(tname, "sms send", phone, ok)
    return ok
end
```

`handleJsonLine` 增加分支：

```lua
elseif obj.cmd == "sms" and type(obj.phone) == "string" then
    sendSms(obj.phone, obj.text)
```

把 `V100C_PASTE_THIS_TO_TASK1.lua` 重新整段粘到银尔达后台任务1（第一行 `function`、最后一行 `end`），即可同时支持打电话和发短信。

## 5. 最小验证脚本

`tools/v100c_min_sms_test.lua`：只做一件事——等网络注册后 `sms.send` 一条测试短信。用于在接正式任务前确认：

- 该固件是否带 `sms` 库；
- SIM 卡是否能发短信。

用法：改占位号码 → 单独粘到任务1 → 启动 → 看测试手机是否收到短信。验证通过后再换回正式 UART 任务脚本。

---

## 6. 中文短信编码注意

- 默认正文是英文，走 7bit GSM 编码，最稳。
- 想发中文：把 `FALL_ALERT_4G_DTU_SMS_TEXT` 改成中文即可，较新的 LuatOS `sms.send` 会把 UTF-8 自动转 UCS2 发送。但中文按 UCS2 计，单条上限约 70 字，过长会被分条或截断。
- 若中文短信乱码，先用 `v100c_min_sms_test.lua` 直接在 lua 里写中文常量测试，确认是固件编码问题还是 JSON 传输问题。

---

## 7. 操作步骤

1. WS63：按需设置 `FALL_ALERT_4G_DTU_CALL_ENABLED` / `FALL_ALERT_4G_DTU_SMS_ENABLED` 和 `FALL_ALERT_4G_DTU_SMS_TEXT`，重新编译烧录 Board B。
2. V100C：先用 `v100c_min_sms_test.lua` 验证短信能力，通过后把 `V100C_PASTE_THIS_TO_TASK1.lua` 整段粘到任务1并启动，同步到设备。
3. 触发跌倒：手机应先收到短信、随后来电。

---

## 8. 调试检查表

| 现象 | 优先检查 |
| --- | --- |
| 最小脚本就收不到短信 | SIM 是否开通短信、是否注册到网络、`sms` 库是否存在（看日志 `sms lib not available`） |
| 能打电话但收不到短信 | V100C 任务1 是否已换成带 `sendSms` 的新脚本；WS63 `FALL_ALERT_4G_DTU_SMS_ENABLED` 是否为 1 |
| 短信中文乱码 | 见第 6 节，先用 lua 内中文常量定位 |
| 短信内容被截断 | 正文过长；英文≤160 字符、中文≤70 字 |
| 重复触发只发一次 | `FALL_ALERT_4G_DTU_COOLDOWN_MS` 默认 60s 合并，是正常保护 |

> 仓库只保留占位号码（`<TARGET_PHONE>` / `123xxxx4567`），真实号码只放本地 WS63 配置。
