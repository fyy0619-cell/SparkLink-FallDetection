# 硬件接线速查 (Hardware Wiring Cheat Sheet)

> 一页纸列完两块 WS63 + 周边外设的全部接线、引脚、供电、模式位。
> 板间通信用 SLE/BLE,**无线**,不需要接线;有线接线只在每块板"对外设"那一段。

---

## 0. 板分工

| 板 | 角色 | 文档代号 | 主要外设 |
| --- | --- | --- | --- |
| 板 A | 可穿戴端,采集 + 推理 + 上报 SLE | "**手环板**" | MPU6050(I2C)、电源 |
| 板 B | 网关端,接收 SLE 后做本地+远程报警 | "**网关板**" | WS2812B 灯带、蜂鸣器、LED、V100C 4G、WiFi(板载) |

**注意**:同一根 `GPIO_15/16` 在两块板上是不同功能(I2C vs UART1),靠 `PIN_MODE` 区分,**不要混淆**。

---

## 1. 板 A(手环板)接线

### 1.1 MPU6050 (I2C1, PIN_MODE_2)

| WS63 引脚 | 接到 MPU6050 | 说明 |
| --- | --- | --- |
| `GPIO_15` (I2C1_SDA) | `SDA` | 双向数据,内置上拉,需外部 4.7kΩ 上拉到 3.3V |
| `GPIO_16` (I2C1_SCL) | `SCL` | 时钟,同上 4.7kΩ 上拉 |
| `3.3V` | `VCC` | MPU6050 最高 3.6V,**不能接 5V** |
| `GND` | `GND` | 共地 |

- I2C 总线号:`I2C_BUS_ID = 1`,模式 `PIN_MODE_2`
- MPU6050 默认地址 `0x68`(AD0 接 GND);接 VCC 则变 `0x69`
- 代码已带 **I2C 总线恢复**逻辑:烧录中断/CPU 复位导致 SDA 卡死时会自动用 9 个 SCL 脉冲解锁,无须人工断电

### 1.2 电源
- 主供:`USB Type-C` 5V → 板载 LDO 出 3.3V,直接喂 MPU6050
- 移动方案:MH-CD42 锂电管理 + 3.7V 锂电(详见 `功耗分析.md`)
- 平均电流 ~100mA,峰值 ~250mA;3000mAh 电池约 30 小时

## 2. 板 B(网关板)接线

### 2.1 WS2812B 灯带 (单总线)

| WS63 引脚 | 接到灯带 | 说明 |
| --- | --- | --- |
| `GPIO_10` | `DIN`(数据) | 时序由 RISC-V cycle 计数器精确生成,与编译优化无关 |
| `5V` | `VCC` | 必须 5V,3.3V 灯珠亮度严重不足 |
| `GND` | `GND` | 灯带 GND 与 WS63 GND 必须共地 |

- 不要用 `GPIO_07/GPIO_08`,会跟 UART2 冲突
- 默认 8 颗灯珠,常态绿、告警 2.5Hz 红闪
- 5V 灯珠由 USB 直供,**不要并到 V100C 那路 5V**,峰值电流会拉崩 LDO

### 2.2 蜂鸣器 + LED

| WS63 引脚 | 外设 | 触发逻辑 |
| --- | --- | --- |
| `GPIO_08` | MH-FMD 蜂鸣器 `I/O` | **低电平触发**,空闲时输出高电平 |
| `GPIO_09` | 普通 LED | 高电平点亮 |

- 蜂鸣器另一脚接 3.3V/5V(看型号),通常红正黑负
- 告警时长由 SLE Server 端控制(默认收 `0x05` 后响 10 秒)

### 2.3 V100C / Air780EHV 4G DTU (UART1, PIN_MODE_1)

| WS63 引脚 | 接到 V100C | 说明 |
| --- | --- | --- |
| `GPIO_15` (UART1_TX) | V100C `RXD`(外部 RXD) | **WS63 发**,V100C 收 |
| `GPIO_16` (UART1_RX) | V100C `TXD`(外部 TXD) | V100C 发,WS63 收 |
| `GND` | `GND` | 共地不能省,**信号才有参考** |

- 波特率 115200、8N1
- V100C 那侧用 `UartGetRecChAndDel(2)`,跟外部 RXD/TXD 对应(详见 `4G_DTU_call_sms_guide.md`)
- 板间已经共地,**V100C 单独走 5V 输入**,自带 LDO,不要从 WS63 3.3V 拉电

### 2.4 WiFi(板载,无外接)

- WS63 板载 WiFi 模组,2.4GHz only
- 不能连 5G 频段,手机开热点选"2.4GHz 兼容"

### 2.5 电源

- 主供:**USB 单独喂板 B**(因为 4G 拨号瞬间会拉大电流)
- V100C/Air780EHV:**独立 5V/2A** 电源,跟板 B 共地
- 灯带:独立 5V,共地
- 三路共地一定要拉到同一个 GND 点,否则 UART/I2C 会乱码

| GPIO | 板 A 用途 | 板 B 用途 | 备注 |

## 5. 上电自检(每次插上电要做的事)

1. **目测**:灯带是不是绿色常亮 → 板 B 跑起来了
2. **串口**:接 USB,USB 串口波特率 115200,看到 `[FALL_GW] Wi-Fi connected.` 和 `DHCP success` → 板 B 联网 OK
3. **板 A**:晃一下手环,串口能看到 `[Monitor] state=NORMAL` → MPU6050 通信 OK
4. **拍一下手环**(模拟急动):
   - 板 A 串口出 `[SLE] send alert 0x05`
   - 板 B 串口出 `[CLIENT] 2`,**灯带变红闪 / 蜂鸣器响 / LED 亮**
5. 同一动作下,板 B 串口应出现 `[FALL_GW] fall alert uploaded.` 和 `[DTU] sms ok`

任一步不过就停下来,按 `现场配置速查.md` 的 §4 排错。

---

## 6. 注意!这些东西**不能**接错

- **MPU6050 不能接 5V**,会烧片
- **WS2812B 不能用 3.3V 数据电平**,大部分时候不亮或乱跳;板 B 的 USB 5V 已经足够驱动,直接接
- **板 A 和板 B 之间不要拉数据线**,板间通信靠 SLE 无线,接线只会引入地环路
- **V100C 自带电源,不要从 WS63 拉 5V 给 V100C**,4G 发射瞬间 1.5A 直接把 USB 拉崩
- 烧录时如果烧到一半断电导致 I2C 锁死(SDA 持续低),**断电 5 秒再上电**,或者直接重烧(代码里有自动恢复)
