# 现场配置速查 (Field Configuration Cheat Sheet)

> 给跑现场/演示/换网络的人看的一页清单。不讲原理，只讲**哪个文件改哪一行**和**怎么让手机收到推送**。
> 原理与设计请回去看 `远程报警链路与户外化方案-2026-05-10.md`。

---

## 0. 总览：要改什么去哪儿改

| 想改的东西 | 文件 | 板端/服务端 |
| --- | --- | --- |
| 监护人电话 / 短信内容 / 拨打-发短信开关 | `application/samples/my_demo/fall_detect/inc/fall_alert_4g_dtu_config.h` | WS63 板端 |
| 4G DTU 是否启用 / UART 引脚 / 波特率 | 同上 | WS63 板端 |
| WiFi SSID 和密码 | `application/samples/my_demo/fall_detect/inc/fall_alert_gateway_config.h` | WS63 板端 |
| 后端服务器 IP / 端口 / 路径 / Token | 同上 | WS63 板端 |
| 设备 ID（区分多个手环） | 上述两个 `*_config.h` 各有一个，建议保持一致 | WS63 板端 |
| PushPlus token（决定哪个微信收推送） | `tools/fall_alert_backend.env`（拷贝自 `.env.example`） | PC/服务器 |
| 推送通道（dryrun / pushplus / tencent） | 同上 `FALL_NOTIFY_PROVIDER` | PC/服务器 |

板端的两个 `*_config.h` 都改完之后必须 **重新编译 + 烧录**，不是热生效。
后端的 `.env` 改完之后只要**重启 `fall_alert_backend_demo.py`** 即可。

## 1. 改监护人电话和短信（4G DTU 链路）

文件：`application/samples/my_demo/fall_detect/inc/fall_alert_4g_dtu_config.h`

只需关心这几行：

```c
#define FALL_ALERT_4G_DTU_ENABLED      1                /* 不用 4G 就改 0，可省一路 UART */
#define FALL_ALERT_4G_DTU_PHONE        "18573050268"    /* ← 改成监护人手机号 */
#define FALL_ALERT_4G_DTU_CALL_ENABLED 1                /* 拨打开关 */
#define FALL_ALERT_4G_DTU_SMS_ENABLED  1                /* 短信开关，两者可单独关 */
#define FALL_ALERT_4G_DTU_SMS_TEXT \
    "Fall detected. Please check on the elder immediately."  /* 短信正文，不要带 " 或 \ */
#define FALL_ALERT_4G_DTU_COOLDOWN_MS  60000U           /* 报警冷却，避免一跌连拨 */
```

注意点：

- **真实测试前一定改 `FALL_ALERT_4G_DTU_PHONE`**，默认那个是开发用号，乱试会骚扰别人。
- V100C/Air780EHV 端的 `dtu_task_fall_alert.lua` 里有一个 `outgoing_number = "123xxxx4567"` 只是兜底默认值，**真实号码是 WS63 通过 JSON 下发的**，所以 Lua 那边不用动。
- 想临时只测短信、不打电话：把 `FALL_ALERT_4G_DTU_CALL_ENABLED` 设 0；反之同理。
- UART 接线确认：WS63 `GPIO_15(TX) -> V100C RXD`，`GPIO_16(RX) <- V100C TXD`，共地。

## 2. 改 WiFi 云端上报 + 微信推送（PushPlus 链路）

这条链路是比赛/室内演示的主力，由 **板端 HTTP POST → 后端服务 → PushPlus → 微信** 四段组成。

### 2.1 板端 WiFi 和后端地址

文件：`application/samples/my_demo/fall_detect/inc/fall_alert_gateway_config.h`

```c
#define FALL_GATEWAY_WIFI_ENABLED   1
#define FALL_GATEWAY_WIFI_SSID      "OPPO Find X9s Pro"     /* ← 换成你现场的 2.4G 热点名 */
#define FALL_GATEWAY_WIFI_PASSWORD  "yyfu0619"              /* ← 热点密码 */

#define FALL_GATEWAY_SERVER_HOST    "10.109.0.184"          /* ← 跑后端那台 PC 的 IPv4，跟手环同一个热点下 */
#define FALL_GATEWAY_SERVER_PORT    8080                    /* 跟后端 `--port` 对得上 */
#define FALL_GATEWAY_SERVER_PATH    "/api/fall-alert"

#define FALL_GATEWAY_DEVICE_ID      "ws63-fall-client-001"
#define FALL_GATEWAY_AUTH_TOKEN     "change-me-demo-token"  /* ← 跟后端 .env 里 FALL_BACKEND_TOKEN 一致 */

#define FALL_GATEWAY_CLOUD_COOLDOWN_MS  60000U
```

要点：

- **必须用 2.4G 热点**。WS63 不连 5G。手机开热点时找一下"2.4GHz兼容/Wi-Fi 兼容"开关。
- `FALL_GATEWAY_SERVER_HOST` 填**跑后端那台 PC 在该热点下的 IPv4**（`ipconfig` 看`无线局域网适配器`下的 IPv4），不是公网 IP，也不是默认网关。换网络/换电脑必改。
- `FALL_GATEWAY_AUTH_TOKEN` 跟后端 `.env` 的 `FALL_BACKEND_TOKEN` 必须**完全一致**，不一致后端会 401。
- 现在的 SSID/密码是测试用值，正式公开演示前建议改成临时热点并替换。
- 改完都要重编 + 烧录。

### 2.2 PC 上准备 PushPlus token

PushPlus 是这条链路里把 HTTP 事件转成"微信公众号消息"的中转，免审核、个人号秒到。

1. 浏览器打开 https://www.pushplus.plus/ ，用微信扫码登录。
2. 在"发送消息 → 一对一"页面拿到你的 **token**（32 位字符串）。
3. 把这个 token 填进下一步的 `.env`。
4. 这个微信号就是收报警的号。换收件人＝换 token。

### 2.3 PC 上配置后端 `.env` 并启动

> 后端代码在 `tools/fall_alert_backend_demo.py`，配置模板在 `tools/fall_alert_backend.env.example`。

1. 拷贝模板：

   ```powershell
   cd tools
   copy fall_alert_backend.env.example fall_alert_backend.env
   ```

2. 编辑 `tools/fall_alert_backend.env`，关键字段：

   ```ini
   FALL_BACKEND_TOKEN=change-me-demo-token   # 跟 WS63 的 FALL_GATEWAY_AUTH_TOKEN 一致
   FALL_RATE_LIMIT_SECONDS=60

   FALL_NOTIFY_PROVIDER=pushplus             # 从 dryrun 改成 pushplus
   FALL_NOTIFY_DRY_RUN=0                     # 实跑要置 0；dry run 时只打印不发推送
   FALL_NOTIFY_CHANNELS=sms,voice            # 给 tencent 用的，pushplus 时不影响

   PUSHPLUS_TOKEN=你的32位token              # 来自 2.2
   PUSHPLUS_CHANNEL=wechat
   PUSHPLUS_TOPIC=                           # 一对一推送留空；要群推再填
   ```

3. 加载环境变量并启动后端（PowerShell 示例）：

   ```powershell
   Get-Content fall_alert_backend.env | ForEach-Object {
       if ($_ -match '^\s*([^#=]+)=(.*)$') { $env:($matches[1].Trim()) = $matches[2].Trim() }
   }
   python fall_alert_backend_demo.py --host 0.0.0.0 --port 8080
   ```

   Bash/WSL 用户：

   ```bash
   set -a && source fall_alert_backend.env && set +a
   python fall_alert_backend_demo.py --host 0.0.0.0 --port 8080
   ```

4. PC 防火墙放行 8080（首次启动时 Windows 会弹"是否允许 Python 网络访问"，选**专用网络**）。

### 2.4 链路验证

按这个顺序点检，任何一步不过就停在那一步排查：

1. WS63 上电后串口能看到 `Wi-Fi connected.` 和 `DHCP success, ip=...`。
2. PC 上 `ping <WS63 的 IP>` 通。
3. 在 PC 上手动打一发：

   ```powershell
   curl.exe -X POST http://127.0.0.1:8080/api/fall-alert ^
     -H "Authorization: Bearer change-me-demo-token" ^
     -H "Content-Type: application/json" ^
     -d "{\"device_id\":\"ws63-fall-client-001\",\"event\":\"fall\",\"payload\":1,\"event_count\":1}"
   ```

   后端控制台应打印 `[NOTIFY] pushplus ok` 之类，微信应几秒内收到。
4. 真跌一下手环（或敲一下），WS63 串口看到 `fall alert uploaded.`，后端打印同样的 `pushplus ok`，微信收到。

## 3. 改设备 ID（多个手环共存时）

两个文件各有一个 `*_DEVICE_ID`，都改成同一个值，例如：

```c
/* fall_alert_4g_dtu_config.h */
#define FALL_ALERT_4G_DTU_DEVICE_ID  "ws63-fall-alice"

/* fall_alert_gateway_config.h */
#define FALL_GATEWAY_DEVICE_ID       "ws63-fall-alice"
```

后端会把 device_id 透传到推送正文，多手环时**靠这个字段区分是谁跌倒的**。

## 4. 常见踩坑

| 现象 | 多半是 |
| --- | --- |
| WS63 一直停在 `AP not found, retry.` | SSID 拼错 / 用了 5G 频段 / 热点没开 |
| 一直 `DHCP timeout` | 密码错 / 路由器 MAC 过滤 |
| `connect server failed.` | `FALL_GATEWAY_SERVER_HOST` 填的不是 PC 当前 IPv4，或者不在同一热点 |
| 后端日志 `401 unauthorized` | `FALL_GATEWAY_AUTH_TOKEN` 跟 `FALL_BACKEND_TOKEN` 不一致 |
| 后端日志 `200 ok` 但微信收不到 | `FALL_NOTIFY_DRY_RUN=1` 没改 / `PUSHPLUS_TOKEN` 不对 / `FALL_NOTIFY_PROVIDER` 还是 `dryrun` |
| 跌一次连发多条推送 | 调高 `FALL_GATEWAY_CLOUD_COOLDOWN_MS` 和后端 `FALL_RATE_LIMIT_SECONDS` |
| 短信带乱码 | 短信正文里出现了 `"` 或 `\`，删掉重新编译 |
| 短信 `drop alert because phone is still placeholder` | `FALL_ALERT_4G_DTU_PHONE` 还是 `YOUR_PHONE_NUMBER` 占位符，没改 |

## 5. 最小回归用例（演示前 5 分钟跑一遍）

1. `git pull` 拉到最新（含本速查）。
2. 改 `fall_alert_gateway_config.h` 的 SSID / 密码 / `SERVER_HOST` 为本场环境。
3. 改 `fall_alert_4g_dtu_config.h` 的 `FALL_ALERT_4G_DTU_PHONE` 为现场手机。
4. `python build.py ws63-liteos-app` 重编 + 烧录。
5. PC 上把 `tools/fall_alert_backend.env` 的 token 填好，`python fall_alert_backend_demo.py --port 8080` 起服务。
6. 按 §2.4 验证 4 步。
7. 现场跌 1 次 → 微信收到推送 + 监护人手机收到短信/电话。
